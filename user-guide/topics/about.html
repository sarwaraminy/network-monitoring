About Network Monitoring

What this application watches for, and what it does when it finds something.

Network Monitoring watches traffic on a network segment and raises a finding when it sees something worth a person's attention. It stores each finding, decides whether to tell anybody, and keeps a record of what was done about it.

The application is in two halves, and it is worth knowing which half you are looking at on any screen:

  • Detection decides what happened. A detector is a single check — a port scan, an ARP reply that contradicts what was seen before — and it never touches the database.
  • Delivery decides what to do about it: whether the finding is stored, whether it is suppressed, and whether an email, a chat message or a syslog record leaves the machine.

Nothing on the delivery side can stop detection. A dead webhook or a rejected SMTP password cannot prevent a finding being recorded — every such failure ends in a log line and, where you can see it, a message on the Delivery page.

What it detects

DetectorSeverityWhat it means
ARP spoofingCriticalAn address on the network was claimed by a MAC address that does not match what was seen before — the signature of a machine-in-the-middle attempt against the gateway.
Cleartext credentialsCriticalA username and password crossed the network unencrypted (HTTP Basic, a login form, FTP, Telnet, POP3/IMAP, SMTP AUTH). The password is never recorded — only the username and the secret's length.
Port scanHighOne host contacted many ports on another in a short window.
Host sweepMediumOne host probed many addresses on the segment, typically one port each.
SYN floodMediumA burst of connection attempts with no completed handshakes.
DNS tunnellingHighLong, high-entropy names queried repeatedly against one domain — data moving over DNS.
Threat intelligenceHighA conversation with an address or domain that appears on an indicator feed you configured. Off until you turn it on; see Threat intelligence.
New deviceLowA MAC address not seen before appeared on the segment.

What it does not do

  • It does not block anything. This is a monitoring tool, not a firewall. It tells you; acting on it is yours.
  • It only sees traffic that reaches it. Running on an ordinary workstation, it sees that workstation's own traffic plus broadcasts — which is the most common reason a new installation appears to find nothing. Seeing a whole segment needs a mirror (SPAN) port or a network TAP.
  • It does not read encrypted payloads. Cleartext-credential detection finds credentials precisely because they were not encrypted.
