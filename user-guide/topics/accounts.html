Accounts

How accounts come to exist, and who may create one.

The rules

Account creation follows three rules, in this order:

  1. An administrator can create any account, at either role.
  2. On an installation with no accounts at all, exactly one can be created without permission, and it is forced to ADMIN. Otherwise there would be no way to create the second. The window shuts the instant an account exists.
  3. Otherwise, account creation is refused — unless the server has open signup switched on, in which case anybody may create an account and it is always a USER.

A requested role is treated as a suggestion, never an instruction. It is honoured only for an authenticated administrator, and discarded entirely under open signup. A public form that could create administrators is exactly the hole this replaced.

Open signup

Open signup is off by default. An administrator turns it on with ALLOW_OPEN_SIGNUP=true in api/.env on the server, followed by a restart. Even then it can only ever produce USER accounts.

The language on the form

The sign-up form asks for a language alongside the name and password. It sets the one the account starts in on a device where the person has not chosen otherwise — the switch in the account menu overrides it per browser, and neither affects anybody else. See Language.

The choices are English, Deutsch and دری — the three the interface is actually translated into. The form previously offered Pashto, which the application has no translation for, and omitted German, which it does: an account created as Pashto would simply have read English with no indication why.

Changing a role afterwards

An account's role can be changed at any time in Administration settings → Users and roles — it no longer needs a shell on the server. See Who can do what for the two changes that are refused and why.

Creating accounts from the server

Accounts can also be managed from a shell on the server, which is how the first one is usually made and how a forgotten password is recovered:

npm run user -- list
npm run user -- create --email you@example.com --password 'a good one' --role ADMIN
npm run user -- set-password --email you@example.com --password 'a new one'
npm run user -- delete --email old@example.com

Passwords are hashed before they are stored, by the same code path the application uses.

Who can use this

Creating an account requires an administrator, except for the single first-account case above. Nobody, at any role, can read another account's password.
