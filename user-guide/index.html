If you are here because an alert did not arrive

Work down this list; each step is a screen in this guide.

  1. Was it detected at all? Security alerts, with Open only switched off. If it is not there, the question is about detection or a suppression rule, not delivery.
  2. Was it suppressed? Suppression rules — the Hidden column counts what each rule has dropped.
  3. Is a channel configured, and is delivery on? Alert delivery. The page says both, and names the reason when a channel is configured but cannot authenticate.
  4. Did a limit hold it back? Same page: minimum severity, the digest window, the per-finding throttle and the hourly ceiling are each a reason something you expected did not arrive.
  5. Can the channel actually be reached? Send test, and read the per-channel results rather than the summary.

A note on what this application is

It watches and it tells you. It does not block anything, and it only sees traffic that reaches the machine it runs on — on an ordinary workstation, that is that workstation's own traffic plus broadcasts, which is the most common reason a new installation appears to find nothing.

Screenshots in this guide were taken from the running application against a small set of representative findings. The addresses and host names in them come from the ranges reserved for documentation; they are not a real network.
